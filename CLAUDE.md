# Climb and Slide for Eggs: BACKEND (game server)

Frontend (3D client) lives at `../Climb-and-slide-for-eggs`. Colyseus + Mongo. "Backend" means this folder.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`), joined with `joinOrCreate("world", { token, userId, username, pfp })`. Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; `guest-` ids are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- **Identity** (`src/bloxity.ts`): when `BLOXITY_API_URL` is set (or `NODE_ENV=production`) a player's id only counts if `Legion.SDK.auth.getToken()` verifies (`POST /v1/auth/game-token/verify`); the bare `userId` is ignored. Locally the sent `userId` is trusted. A verified token's `carriedFrom` guest ids hand their save to a new account once (`carryOver`).
- Messages client -> server: `saveProgress` (flat partial snapshot of the changed sections), `identify` (same options as join, after a sign-in/out), `claimDaily` { day }, `dailyRefresh`, `adReward` { placement, rewardToken }. Server -> client: `progress` (saved doc, sanitized), `noProgress` (new account / guest / no database: the client keeps its state and saves it), `serverError` (save unreadable: saving stays off), `daily`, `dailyResult`, `adResult`. Saves are ignored until the session's load has answered. A second live session on one account is evicted.
- Saved shape (`PlayerDoc`, flat; the client's `src/saves.js` maps its sections onto it): `best` (`$max`), `strength`, `eggs[]` (hotbar tier indexes), `auto`, `cash`, `cashAt`, `placed[{tier,x,z}]`, `pets[{id,on}]`, `baseLevel`, `weightsOwned[]`, `weightEquipped`, `rebirths`, `indexEggs[]`, `indexFound[]` ("tab:petId"), `sellAuto`, `paws`, `lastSeen`.
- Daily Rewards (`src/daily.ts`): server-authoritative on UTC days, fields `dailyDay`/`dailyLast`/`dailyClaimed` never come from `saveProgress`. The client pays a day only after `dailyResult.ok`.
- Rewarded ads: `adReward` verifies the token with `POST /v1/ads/reward/verify` (single-use, placement must match, user must match) before `adResult.ok`. Placements in `AD_PLACEMENTS`.
- Stats: saves are batched to `POST /v1/games/{BLOXITY_GAME_ID}/stats` every `STATS_EVERY_MS` (needs `BLOXITY_REPORT_TOKEN`; skipped without). The user id is reported as `legion_<_id>`: confirm this mapping on the first deploy (`dropped.invalid_user` in the response means it is wrong). Leaderboards are submitted by the client SDK.
- Gems / purchases are not implemented (out of scope).
- `src/constants.ts` bounds must cover the client's `src/config.js`. A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes; pushes also build+push a GHCR image and deploy to Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` (keep 2-100). Needs `LEGION_GAME_ID` (= `climb-and-slide-for-eggs`, the client's `GAME_SLUG`) and secret `LEGION_DEPLOY_TOKEN`.
